# 内存优化与验证

本轮优化针对后台驻留、图片解码和播放器资源。改动后的实际内存收益需要安装同签名的 Release APK，在同一设备和浏览流程下对比，不能由缓存容量推算。

## 已实现的策略

- 消息通知只由 JobScheduler 调度；重复进入前台不重置相同周期任务。请求结束必须完成 Job，停止任务会取消请求并忽略迟到的回调。
- Sketch 图片缓存最多 24 MiB，Bitmap 复用池最多 8 MiB；低内存设备分别为 12/4 MiB，且不超过库原有预算。全部 Activity 退后台 30 秒后清理两者，回前台取消待执行清理。
- GIF 优先扫描帧元数据，扫描最多 8 MiB。其他必要的动画探测限制为 1×1 像素，保留单帧格式兼容与正式解码器的尺寸采样。
- 原生页面请求使用已缓存的 WebView UA 或已有备用 UA。真实 WebView 创建后才更新 UA；后台暂停网页，离开页面时保存导航状态并销毁实例，恢复失败时回退到最近 URL。
- 签到子进程跳过图片生命周期、图标、页面回调、屏蔽列表和表情初始化，保留账号、API 和通知配色所需初始化。
- 视频仅在拖动进度条时创建预览播放器，预览视图释放后停止其缓冲和延迟 seek。
- 列表合并减少拼接和去重的临时集合。保留全部历史帖子及原有刷新、楼层定位语义；本轮未实现有界分页窗口。

图片清理不会销毁仍被页面引用的位图。HEIF 动画探测对象没有公开的原生 close 接口，其原生资源仍由系统回收；输出像素已经限制为 1×1。单帧 GIF 保留既有 Movie 回退。`largeHeap` 和 R8 保留规则本轮未修改。

## GitHub Actions

发布工作流执行 `testReleaseUnitTest assembleRelease`，包含 GIF 元数据解析、列表合并及既有回归测试。编译和 APK 构建只在 Actions 中进行。

## 安装后的验证流程

1. 冷启动进入首页，确认关注、推荐、消息和登录状态正常；打开网页再返回，检查网页后退历史和再次进入时的恢复。
2. 浏览相同数量的帖子、静态图片、单帧 GIF、动图及大图，检查显示与滚动；重复前后台切换，短暂切换不应反复清空图片缓存。
3. 播放视频，反复拖动进度条（含快速松手后再次拖动）、切换全屏、退出页面，确认预览和主播放正常。
4. 退后台 30 秒、2 分钟分别采样 `adb shell dumpsys meminfo com.huanchengfly.tieba.post`。记录 PSS、Java Heap、Native Heap、Graphics，并记录关联的 WebView 渲染进程；不用 RSS 与 PSS 混比。
5. 用 `adb shell dumpsys activity services com.huanchengfly.tieba.post` 确认通知 Job 完成后没有额外 started service 驻留。系统可能因其他绑定或最近使用状态保留进程，不能要求退出后立即消失。
6. 长时间浏览后再次采样，检查内存是否随重复相同操作持续增长；需要堆转储或原生分配分析才能进一步认定泄漏。
